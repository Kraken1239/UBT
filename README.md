# UBT.AI — адаптивная подготовка к ЕНТ

Учебный MVP: диагностический тест → разбор ошибки → практика по тому же навыку → самостоятельная проверка → обновление прогресса. Интерфейс: русский, казахский, английский.

## Запуск

Нужен Python 3.12 или новее. Внешние Python/npm-зависимости и сборка не требуются.

```sh
cd /workspace/UBT
python3 server.py --port 8000
```

Открывайте приложение через этот сервер. Статический хостинг, включая GitHub Pages, больше не поддерживает аккаунты и API. Сервер по умолчанию слушает только loopback. Для разработки вне облачной среды рабочий каталог — корень клонированного репозитория.

Создайте аккаунт с email и паролем от 10 символов. Выберите профильную пару и язык; доступны 3 обязательных и 2 профильных предмета. На RU и KK пока по одному диагностическому и повторному демозаданию на каждый из 10 предметов; EN сохраняет 50 диагностических и 50 повторных заданий прежнего прототипа. Итого 70 диагностических и 70 повторных демозаданий. Это короткие примеры, не полноценный пробный ЕНТ.

## Что реализовано

- Регистрация и вход; scrypt-хеши паролей, HttpOnly/SameSite cookies, серверные сессии с истечением через 7 дней, выход из текущей сессии.
- SQLite: профиль, история тестов, ошибки, повторные проверки и AI-обратная связь. Вход с другого устройства на **тот же сервер и базу** даёт тот же прогресс.
- Подсчёт результатов на сервере; ключи ответов и объяснения не передаются до завершения теста. Повторная отправка результата не создаёт новую попытку.
- Таймер на 5 минут. Есть короткий 10-секундный запас для сетевой доставки автоматической отправки; после него ответы не засчитываются. Уход со страницы предупреждает о потере незавершённого теста.
- Подготовленный разбор и AI-разбор рассуждений ученика, если настроен ключ. Режим ответа явно указан.
- Первую попытку повторного задания нельзя перезаписать. После успешного ответа показывается «Первичное понимание»; повтор доступен через 24 часа. В демоверсии повторяется тот же пример — это **не доказательство освоения нового задания или долговременного закрепления**.
- Импорт банка с валидацией схемы, источником, правами использования и сведениями о проверке. При наличии проверенных вопросов по предмету/языку диагностика выбирает их вместо демозаданий.
- Локальные CSS/JS, без внешних CDN. Русский/казахский/английский интерфейс; исторические формулировки сохраняются на языке исходной попытки.

## OpenAI

Сервер обращается к `https://api.openai.com/v1/chat/completions`. Задайте секрет `UBT_AI_API_KEY` через настройки среды или защищённое окружение процесса. Резервно поддерживается существующий `OPENAI_API_KEY`. Не записывайте ключи в репозиторий и не присылайте их в чат.

Необязательная переменная `UBT_AI_MODEL` — по умолчанию `gpt-4.1-mini`. Нужен доступ к этой модели. Без ключа работает подготовленный разбор; он не выдаётся за AI-анализ. Сбой AI показывается явно, подготовленный разбор остаётся доступен. Лимит: 20 запросов AI на аккаунт в час. Эти ограничения локальны процессу, не заменяют бюджет провайдера.

AI получает текст вопроса, выбранный ответ, эталонный разбор и введённое учеником рассуждение. Пароль, email и ключ повторного задания в запрос не включаются. Объясните передачу данных внешнему провайдеру участникам пилота; не вводите личные данные в рассуждение. Ответы AI могут быть ошибочны. Подключение проверено тестовым ответом и симуляцией отказа; реальный запрос без ключа не проверялся.

## Банк вопросов

См. [схему и правила импорта](content/README.md). Все встроенные вопросы — **demo**, а не официальный/проверенный банк. Наличие отметки `reviewed` означает утверждение оператора о проверке, а не автоматическую проверку качества системой.

```sh
python3 server.py validate-bank /path/to/bank.json
python3 server.py import-bank /path/to/bank.json
# Перезапустите сервер, чтобы загрузить импорт.
```

## Проверки

```sh
python3 -m unittest discover -s tests -v
# Совместимый прежний вход, если установлен Node.js:
node verify.cjs
# Дополнительно: Chromium и Python Playwright должны быть установлены.
python3 tests/browser_smoke.py
```

Серверные тесты используют временную базу и локальный HTTP-сервер. Браузерный сценарий использует отдельные временные данные, проверяет вход из двух браузеров, перезапуск, казахский интерфейс и мобильную ширину. Прикладные данные не затрагиваются.

## Хранение и размещение

По умолчанию данные находятся в игнорируемом `.data/`. `UBT_DATA_DIR` меняет каталог. При публичном размещении нужен постоянный диск; разные независимые копии базы не синхронизируются автоматически. Для согласованной резервной копии используйте SQLite backup API; вместе с ней сохраните `imported.json`. Не копируйте только основной файл SQLite во время записи без WAL-файлов.

Для размещения за HTTPS-прокси задайте `UBT_ORIGIN=https://your-domain` и `UBT_SECURE_COOKIES=1`. При необходимости слушайте внутренний интерфейс: `python3 server.py --host 0.0.0.0 --port 8000`. Не публикуйте напрямую Python development server: для реального запуска нужны обслуживаемый HTTPS-прокси, управление процессом, резервное копирование, мониторинг и проверка безопасности.

Email пока не подтверждается, сброса забытого пароля нет. Проверенный двуязычный банк, преподавательская редактура, реальные учебные результаты и готовность платить требуют отдельной работы и полевого пилота. Существующие локальные профили старой версии автоматически не переносятся: владение одним введённым email не доказывает владение аккаунтом.
